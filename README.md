# aisofttechsolution.com

Website for **AI Soft Tech Solution** — AI automation and custom apps for online
sellers and small businesses. Vite + React 19 SPA on Vercel, with Firestore for
blog posts, blueprints, FAQs, testimonials and contact messages.

## Run locally

```bash
npm install
npm run dev        # http://localhost:3000
npm run build      # production build in dist/
npm run lint       # type-check
```

## Where content lives

| What | File |
|---|---|
| Projects on the homepage and `/work` | `src/data/projects.ts` |
| Services (section, navbar, structured data) | `src/data/services.ts` |
| Demo apps (`/demos`, homepage) | `src/data/demos.ts` + `public/demos/<slug>/index.html` |
| Free guides | `src/data/guides.ts` + the guide page components |
| Company facts, founder, social links | `src/config/business.ts` |
| FAQ defaults | `src/constants.ts` (Firestore `faqs` overrides them) |
| Blog posts | Firestore `posts`; queued posts in `blog-queue/posts.mjs` (published daily by the GitHub Action) |
| Testimonials | Firestore `testimonials` — shown only after approval in the admin console |

Rule: everything shown on the site must be real. No placeholder projects,
stock photos presented as work, invented statistics or sample testimonials.
Numbers on the homepage are counted from the data files above.

## SEO / GEO / AEO — how crawlers see the site

The site renders in the browser, but most AI crawlers do not run JavaScript.
`middleware.ts` therefore serves bots real HTML:

- **Static routes** → snapshots in `public/prerendered/`, generated by `prerender.mjs`.
- **Blog and blueprints** → rendered live from Firestore by `api/*-prerender.ts`.
- **Unknown URLs** → a real 404 status.
- `/sitemap.xml` → `api/sitemap.ts` (static pages + demos + live blog and blueprint URLs).
- `public/llms.txt` → generated from the data files.

### After changing content

```bash
npm run build && npx vite preview --port 4173   # keep running in a second terminal
npm run prerender   # regenerates public/prerendered/*.html (fails if a canonical, H1 or stat is wrong)
npm run thumbs      # regenerates demo screenshots in public/demos/thumbs/
npm run llms        # regenerates public/llms.txt
```

Commit the regenerated files. When you add a route, add it to `routes` in
`prerender.mjs`, `STATIC_SNAPSHOTS` in `middleware.ts` and `STATIC_PAGES` in
`api/sitemap.ts`.

## Deploying Firestore rules

`firestore.rules` is not deployed by Vercel. After changing it:

```bash
firebase deploy --only firestore:rules
```

## Environment variables (Vercel)

| Name | Used by |
|---|---|
| `GEMINI_KEY_1` … `GEMINI_KEY_5`, `GEMINI_KEY_PAID` | `api/chat.ts` |
| `GEMINI_MODEL` (optional, default `gemini-3.6-flash`) | `api/chat.ts` |
| `FIREBASE_SERVICE_ACCOUNT_JSON` (GitHub secret) | daily blog publish workflow |

The 3D dental demo at `/demos/family-dental/` is proxied from its own Vercel
deployment — keep that rewrite before the generic demo rewrite in `vercel.json`.
